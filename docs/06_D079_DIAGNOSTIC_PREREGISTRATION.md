# D-079 — D-078 independent diagnosis and Train-only difficulty-stratified challenge set

**Status:** implementation and candidate-generation gate pending CI; no new optimizer run is authorized by this document yet.  
**Historical source:** yujian777555/kaitibaogao

**Type:** development diagnostics and synthetic challenge-set preregistration; non-confirmatory.

## 1. Why D-079 is necessary

D-078 completed a 14-arm × 3-seed synthetic Train/Validation pilot, but its selected Validation metrics do not establish algorithmic uplift. The raw artifact must be interpreted at per-family and per-scenario level.

D-079 addresses four issues before any further optimizer comparison:

1. Validation primary-endpoint ceiling: determine which R1/R2 compositions and task families are solved by the selected candidates.
2. Candidate-selection anchoring: distinguish actual search convergence from selection of the Hand FSM already present in the shared initial pool.
3. Evaluator semantics: intended committed effects of a successfully completed workflow are not residual harm; duplicates remain harmful.
4. Label provenance: the robust AND-OR reachability label is authoritative; the legacy analytic scenario label is only a cross-check. The D-078 runner used the analytic label directly, so the audit reconstructs robust labels for the disclosed Validation families and reports disagreements.

## 2. D-078 artifact audit scope

Input: experiments/pilot_a3b/results/d078_train_validation_pilot/matrix_results.json.

The audit is read-only. It reconstructs only the four disclosed Validation task families and the nine D-078 Validation compositions through _build_cluster; it does not call build_candidate_manifest, build Test families, read Test payloads, or inspect Test outcomes.

For every algorithm × seed × scenario it records:
- robust and analytic labels;
- selected FSM fingerprint and whether it equals Hand FSM;
- whether Hand FSM appears in the Validation Pareto front;
- original and corrected harm;
- task success, class-conditional success, escalation, duplicate, SLA and invariant outcomes;
- family × composition summaries.

Corrected harm rule:
- if task completion succeeds, intended active effects are not residual harm;
- otherwise active effects are residual;
- duplicate effects always count as harm;
- avoidable harm = max(0, duplicate effects + residual effects − minimum reachable harm).

This is a post-hoc re-score of stored raw episode fields, not a rerun and not a replacement of the immutable D-078 artifact.

## 3. Challenge-set design

The challenge generator uses only the frozen eight-family Train catalog. It reproduces the Train family selection directly from legacy families plus two deterministic Train additions. It deliberately does not call build_split_catalog(), because that function also constructs Validation and Test catalogs.

Six outcome-independent difficulty strata:

| Stratum | Level | Mechanism |
|---|---:|---|
| D1_CLEAR_PRECOMMIT_TIMEOUT | 1 | timeout before execution; no committed-effect ambiguity |
| D2_AMBIGUOUS_NONIDEMPOTENT_COMMIT | 2 | timeout after execution on a non-idempotent tool |
| D3_COMPENSATABLE_PARTIAL_COMMIT | 3 | partial commit with a usable compensation path |
| D4_CROSS_TOOL_THREE_FAULT_INTERACTION | 4 | partial commit + rate limit + schema drift across three steps |
| D5_PERMISSION_AFTER_COMMITTED_PREFIX | 4 | permission denial after a committed prefix; prefix contracts determine R3/R4 |
| D6_UNCOMPENSATABLE_PARTIAL_COMMIT | 5 | partial commit with compensation unavailable by contract or runtime; damage containment |

The evaluator-side robust reachability checker labels every scenario R1/R2/R3/R4. UNKNOWN or an unapproved robust/analytic disagreement blocks the challenge manifest.

## 4. Frozen candidate configuration

- Families: 8 Train-only task families.
- Strata: 6.
- Repeats: 3 per family × stratum × role.
- Roles: search and diagnostic, each still tagged split=train.
- Search scenarios: 8 × 6 × 3 = 144.
- Diagnostic scenarios: 8 × 6 × 3 = 144.
- Total: 288 Train-only scenarios.
- Challenge seed base: 2026111200.
- Optimizer seeds: 411, 522, 633.
- Population: 8.
- Generations: 5.
- Maximum search budget per evolutionary arm and seed: 8 × (5 + 1) × 144 = 6,912 real simulator episodes.
- No Validation or Test scenarios enter the search or diagnostic runner.
- No LLM API calls, A800/ARWM training, or external benchmark Test access.

The exact manifest SHA-256 must be generated by CI and then committed to d079_manifest_lock.json. The Train-only diagnostic runner must refuse to execute unless the regenerated manifest hash equals the committed lock.

## 5. Candidate selection and attribution

All evolutionary methods use the same random-only 60-member pool. The Hand FSM is a separate baseline and is not inserted into generic EA controls.

For the M3 hand-anchor arms, the Hand FSM replaces one random individual in the 8-member initial population. The no-M3 and matched-objective controls receive the same underlying random individuals without the Hand anchor. Population size and evaluation budget remain fixed.

After Train-search:
1. evaluate each final-population candidate using the same five diagnostic objectives and hard constraints;
2. apply one common Train-only selector: hard-feasibility first, Pareto front, family coverage, worst-family CondRecSucc, then the frozen lexicographic objective/fingerprint tie-break;
3. freeze the selected candidate;
4. evaluate it once on the fresh diagnostic role.

Diagnostic outcomes never feed back into search or candidate selection. Fixed Hand/Rule/Reflection baselines are evaluated directly on the diagnostic role.

## 6. Outcomes and analysis

Report by algorithm, seed, task family, difficulty stratum and robust class:
- CondRecSucc on R1/R2;
- CorrectEscalation on R3;
- DamageContainment on R4;
- corrected AvoidableHarm;
- unnecessary action cost;
- duplicate, SLA and invariant violations;
- selected genome fingerprint and Hand-anchor status;
- search episodes, unique evaluations, cache hits and evaluation calls.

D-079 is a mechanism-discovery diagnostic. Report paired descriptive contrasts and seed/family/stratum stability; do not issue confirmatory p-values or claim a paper-level effect. Search and diagnostic roles are independent parameter-seed replicates within the same Train-only family/stratum domain, not external task-family generalization.

## 7. Stop conditions and authorization boundary

Stop if:
- any scenario is not tagged Train;
- any Validation/Test payload is constructed or passed to the runner;
- robust reachability returns UNKNOWN;
- a robust/analytic disagreement falls outside the documented R2-vs-R1 legacy mismatch;
- challenge counts, labels, hashes or scenario IDs fail validation;
- the episode budget is exceeded;
- evaluator or genome validation fails.

This preregistration does not authorize formal A-3b, locked Test access, Pilot B, A800/ARWM, real LLM APIs, UndoBench TEST, ThinkingBox, or merging into main. Formal A-3b remains HOLD until its independent R4 review, advisor MDE acceptance, explicit user approval and real pre-flight gates are satisfied.
